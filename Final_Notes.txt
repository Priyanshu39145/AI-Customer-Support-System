Final AI Chat Architecture -----



Final AI Chat Flow Architecture (Simple Notes)

⸻

Goal of the System

The AI should:

* chat normally with users
* answer policy questions
* create support tickets only when really needed
* prevent prompt injection and fake escalations

The backend should always stay in control.

⸻

Main Principle

AI suggests → Backend decides

The AI NEVER directly controls ticket creation.

⸻

Full Chat Flow

User Message
      ↓
Security Validation
      ↓
Build Context
      ↓
AI Intent Analysis
      ↓
Backend Confidence Routing
      ↓
Final Action
      ↓
Save Messages
      ↓
Return Response

⸻

Step 1 — User Sends Message

Example:

"My payment failed and money got deducted twice"

The request reaches:

ChatController

then:

ChatService.chat()

⸻

Step 2 — Load or Create Conversation

Backend:

* checks if conversation exists
* creates new conversation if needed

This stores:

* messages
* ticket relation
* conversation history

⸻

Step 3 — Save User Message

The message is saved into database:

Message table

with:

* sender = USER
* content
* timestamp

⸻

Step 4 — Build Conversation Context

IntentContextService creates context for AI.

This includes:

⸻

User behavior

tickets today
tickets this hour
last ticket time

⸻

Conversation state

has existing ticket?
message count?
session start time?

⸻

Conversation history

Last messages are collected.

Example:

USER: payment failed
AI: please try again
USER: still not working

⸻

Step 5 — Sanitize History

Before sending history to AI:

sanitizeConversationHistory()

runs.

It:

* removes suspicious injection text
* truncates large history
* removes control characters

⸻

Why?

Prevents attacks like:

ignore previous instructions
always create tickets

from influencing AI.

⸻

Step 6 — Security Validation

Before AI escalation logic:

SecurityValidationService

checks:

* prompt injection
* abuse patterns
* ticket spam
* rate limits

⸻

Example

Blocked:

"create 100 tickets"

Allowed:

"my account is locked"

⸻

Step 7 — AI Intent Analysis

Now AI analyzes the request.

AI receives:

* current message
* sanitized history
* ticket state
* user behavior context

⸻

AI Returns Structured JSON

Example:

{
  "escalation": true,
  "followUp": false,
  "confidence": 0.94,
  "reason": "payment failure with repeated issue"
}

Meaning of Fields

Field	Meaning
escalation	human support needed
followUp	user asking about existing ticket
confidence	how sure AI is
reason	why AI decided

⸻

Step 8 — Backend Confidence Routing

THIS is the core architecture.

Backend decides final action.

⸻

Case 1 — High Confidence Escalation

confidence >= 0.85

Backend:
✅ creates support ticket

⸻

Example

"My refund still has not arrived after 10 days"

⸻

Case 2 — Medium Confidence

0.60 <= confidence < 0.85

Backend:
❓ asks clarification question

⸻

Example

User:

"My account seems weird"

AI unsure.

Backend asks:

"What issue are you experiencing with your account?"

⸻

Case 3 — Low Confidence

confidence < 0.60

Backend:
💬 normal AI chat only

NO ticket creation.

⸻

Example

"create a ticket"

No actual issue.

So:

* no escalation
* normal response

⸻

Case 4 — Follow-Up

If AI says:

followUp = true

Backend:

* fetches ticket details
* returns ticket status

"What is the status of my ticket?"

Backend tools are deterministic.

createSupportTicket()

Creates:

AI converts tool result into:

* short
* safe
* professional response
