🧠 AI-Powered Customer Support Backend — Authentication System (JWT + OAuth2)

After completing the core backend APIs, I moved to implementing a secure and scalable authentication system. The goal was to support:
	•	Email/Password login (traditional)
	•	Google OAuth2 login (social login)
	•	A unified JWT-based authentication system for all API access

This phase transformed the project into a production-level backend system.

⸻

🔐 PHASE 1: BASIC SECURITY SETUP

I first configured the basic security infrastructure.

Key Configurations:
	•	Disabled default security features:
	•	formLogin() ❌
	•	httpBasic() ❌
	•	csrf() ❌ (since this is a stateless API)
	•	Enabled stateless authentication initially, but later updated to:

SessionCreationPolicy.IF_REQUIRED

👉 This was important because:
	•	JWT = stateless
	•	OAuth2 = needs temporary session

⸻

Beans Created:

In AppConfig:
	•	PasswordEncoder → for hashing passwords (BCrypt)
	•	ModelMapper → DTO mapping
	•	AuthenticationManager → handles login authentication

⸻

🔐 PHASE 2: USER AUTHENTICATION (EMAIL + PASSWORD)

⸻

🧩 User Entity Changes

I modified the User entity to implement:

UserDetails

This allowed Spring Security to:
	•	Treat my User as an authenticated principal
	•	Use roles for authorization

⸻

Added fields:
	•	enabled → whether user can login
	•	providerType → EMAIL / GOOGLE
	•	providerId → unique ID from OAuth provider

⸻

Authority Mapping:

ROLE_USER, ROLE_AGENT, ROLE_ADMIN

Used for:
	•	Role-based access control

⸻

🧩 CustomUserDetailsService

Created to tell Spring:

👉 “How to load user from DB”

loadUserByUsername(email)

This is used internally by Spring during login.

⸻

🧩 Register Flow

Endpoint:

POST /auth/register

Steps:
	1.	Check if email already exists
	2.	Encode password
	3.	Set:
	•	role = USER
	•	providerType = EMAIL
	•	enabled = true
	4.	Save user

⸻

🧩 Login Flow (JWT Generation)

Endpoint:

POST /auth/login

Flow:

Request → AuthController → AuthService → AuthenticationManager


⸻

Detailed Steps:
	1.	Create authentication token:

UsernamePasswordAuthenticationToken(email, password)

	2.	Pass to:

authenticationManager.authenticate(...)

	3.	Internally:
	•	Calls CustomUserDetailsService
	•	Fetches user from DB
	•	Verifies password
	4.	If success:
	•	Returns authenticated User
	5.	Generate JWT:

authUtil.generateAccessToken(user)

	6.	Return:

{
  email,
  role,
  jwtToken
}


⸻

🔐 PHASE 3: JWT IMPLEMENTATION

⸻

🧩 AuthUtil (JWT Utility)

Responsible for:

1. Generating token:

Jwts.builder()
  .subject(email)
  .claim("userId", id)
  .issuedAt(...)
  .expiration(...)
  .signWith(secretKey)


⸻

2. Extracting username:

parseSignedClaims(token).getSubject()


⸻

🧩 JWTAuthFilter (VERY IMPORTANT)

This is the core of request authentication.

⸻

Flow:

For every request:
	1.	Check header:

Authorization: Bearer <token>

	2.	If missing:
👉 Skip → go to next filter
	3.	If present:
	•	Extract token
	•	Get username from token
	4.	Fetch user from DB
	5.	Create:

UsernamePasswordAuthenticationToken(user, null, authorities)

	6.	Set:

SecurityContextHolder


⸻

👉 Now request is authenticated

⸻
